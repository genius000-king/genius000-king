# سرعات

تطبيق أندرويد (Kotlin + Jetpack Compose) يتحكم في سرعة الإنترنت على الجهاز: تختار حدًّا أقصى
(512 Kbps، 1 Mbps، 5 Mbps… أو قيمة مخصصة) وتشغّله وتوقفه بضغطة، مع **سجل تفصيلي لاستهلاكك**.

## ماذا يقدّم

- حدود جاهزة + سرعة مخصصة، وزر تشغيل/إيقاف، وحد منفصل للرفع.
- سرعة حيّة (تنزيل/رفع) مع رسم آخر دقيقة.
- سجل يُحفظ كل دقيقة: آخر ساعة / اليوم / 7 أيام / 30 يومًا، واي فاي مقابل بيانات الجوال، وأكثر التطبيقات استهلاكًا، وتصدير CSV.
- اختيار التطبيقات: الكل، أو المحدد فقط، أو الكل ما عدا المحدد.
- إيقاف تلقائي بمؤقت، وبلاطة في الإعدادات السريعة، وتشغيل عند الإقلاع، وإشعار بالسرعة الحيّة.

## كيف يعمل؟ (الفكرة الأساسية)

أندرويد لا يوفّر لأي تطبيق وسيلة مباشرة لتقليل السرعة. الطريقة الوحيدة بدون root هي `VpnService`:
يفتح التطبيق **VPN محليًا داخل الجوال** فتمرّ كل حزم التطبيقات عليه، ثم يعيد بناء الاتصالات بنفسه:

```
تطبيق ──حزم IP──▶ واجهة TUN ──▶ [TunEngine] ──socket حقيقي──▶ الإنترنت
                                   │
                  دلو رموز (Token Bucket) مشترك للتنزيل وآخر للرفع
```

- **TCP**: ينهي المحرك اتصال التطبيق داخليًا (يرد SYN-ACK ويرتّب التسلسل والنوافذ) ويفتح socket حقيقيًا للوجهة.
  السرعة تُضبط عند **قراءة/كتابة هذا الـsocket الحقيقي**؛ وعند امتلاء المخزن تتكفّل آلية التحكم بالتدفق في TCP
  بإبطاء المرسل بدون إسقاط حزم.
- **UDP**: يُمرَّر عبر sockets مع طابور قصير (≈400ms)؛ ما زاد عن ذلك يُسقط كما يفعل أي اختناق حقيقي.
- **QUIC** (UDP/443) يُرفض بلطف ليعود المتصفح إلى TCP الذي يمكن ضبطه بدقة (قابل للإيقاف).
- الشبكة المحلية وDNS معفاة من الحد.
- لا يمر شيء بخوادم خارجية: كل المعالجة داخل الجهاز.

## هيكل المشروع

| المسار | المحتوى |
|---|---|
| `engine/` | وحدة Kotlin/JVM نقية (بلا أي كود أندرويد): `TunEngine`, `TcpSession`, `TokenBucket`… + الاختبارات |
| `app/…/vpn/` | `SaratService` (خدمة VPN + المراقبة + الإشعار)، البلاطة، مستقبل الإقلاع |
| `app/…/data/` | الإعدادات، قاعدة بيانات السجل (SQLite)، التنسيق |
| `app/…/ui/` | شاشات Compose: الرئيسية، السجل، التطبيقات، الإعدادات |
| `tools/tun-lab/` | مختبر يشغّل المحرك على جهاز TUN حقيقي في Linux ويقيس الدقة بـ`curl` |

## البناء

```bash
./gradlew :engine:test           # اختبارات المحرك (لا تحتاج root)
./gradlew :app:assembleRelease   # app/build/outputs/apk/release/app-release.apk
```

يحتاج JDK 17+ وAndroid SDK (المنصة 36). نسخة الـrelease موقّعة بمفتاح الـdebug لتُثبَّت مباشرة؛
استبدله بمفتاحك قبل أي نشر.

## ما اختُبر فعلًا وما لم يُختبر

- **اختُبر**: المحرك على نواة Linux حقيقية (TUN + `curl`): دقة التحديد 100–106% عند 512 Kbps و777 Kbps و1 و5 و10 Mbps،
  رفعًا وتنزيلًا، وعدالة تامة بين اتصالات متوازية، وإغلاق الاتصالات وإعادة ضبط الوجهات المرفوضة.
- **لم يُختبر**: التشغيل على جوال أندرويد حقيقي (الواجهة رُسمت ورُوجعت بصريًا على JVM). أول ما تثبّته راقب:
  إذن الـVPN، التبديل بين واي فاي وبيانات، ظهور أسماء التطبيقات في السجل.

## حدود معروفة

- IPv4 فقط: مواقع IPv6 فقط قد لا تفتح أثناء التحديد (أندرويد يعيد التطبيقات إلى IPv4 عادةً).
- أجهزة الشبكة المحلية التي تعتمد على البث (Chromecast…) لا تُكتشف أثناء التحديد؛ استعمل «المحدد فقط».
- ICMP (ping) غير مدعوم داخل النفق.
- أرقام السجل تقديرية: بحجم البيانات دون ترويسات الحزم (أقل بنحو 2–4% من عدّاد شركة الاتصالات).
- أندرويد يسمح بـVPN واحد نشط؛ تشغيل «سرعات» يفصل أي VPN آخر.
