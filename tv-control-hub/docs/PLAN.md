# خطة التطوير المرحلية

كل مرحلة تنتهي بشيء **يعمل ويُختبر**، لا بكود نصف جاهز.

| # | المرحلة | معيار الإنجاز |
|---|---|---|
| 0 | الأساس | البناء يعمل، الوحدات، نظام التصميم، CI |
| 1 | **إثبات الجدوى على الجهاز الحقيقي** | صفحة «التشخيص» تؤكد: MediaProjection + المُرمِّز + `dispatchGesture` + أسهم API 33 + قراءات `/sys` |
| 2 | الاتصال والإقران | اكتشاف NSD، مصافحة مشفّرة، موافقة بضغطة، اتصال صامت لاحقًا، إعادة اتصال تلقائية |
| 3 | البث والتحكم | شاشة مباشرة + لمس، ريموت، ماوس، كيبورد، اختصارات |
| 4 | المراقبة | مقاييس حقيقية مع حالة التوفر، رسوم لحظية |
| 5 | الملفات | تصفح، رفع/تنزيل بالأجزاء مع الاستئناف، عمليات الملفات |
| 6 | الخدمات | Shell محدود، جسر Termux، `svc.sh` لإدارة Node/Python و Logs |
| 7 | وضع المشغّل | مشغّل كل التطبيقات، ماوس الريموت، نقل APK من الجوال |
| 8 | التصليب | R8، قياس RAM على التلفزيون، اختبارات E2E، إصدار موقّع |
| مستقبلًا | خارج الشبكة | Tailscale/WireGuard (عنوان يدوي محفوظ — البروتوكول مشفّر طرفيًا أصلًا)، WebRTC فقط إن لزم اختراق NAT |

## قائمة اختبار على الجهاز الحقيقي (المرحلة 1)
1. ثبّت الـ APK على التلفزيون والجوال.
2. `tools/tv-setup.sh <TV_IP>` (أو اتبع قائمة الإعداد في صفحة الرئيسية على التلفزيون).
3. على التلفزيون: الإعدادات ← التشخيص ← «تشغيل الفحص». يجب أن يظهر كل بند ✅ أو سبب واضح.
4. على الجوال: افتح التطبيق ← يظهر التلفزيون ← اتصال ← OK على الريموت.
5. التحكم ← الشاشة المباشرة: يجب أن يظهر البث خلال ثانيتين، واللمس ينفَّذ على التلفزيون.
