# Software profile

Apply to desktop/mobile/web apps, services, developer tools and similar products. Read the existing `examples/graphics-editor.md` when relevant.

Define users, primary journeys, target platforms, explicit technology constraints, data sensitivity/permissions relevant to functionality, reliability, accessibility and performance. Make a complete critical journey run early, including persistence and recovery where required.

Compare major libraries/frameworks against representative risks and current capabilities. Avoid unnecessary rewrites. Record interfaces, data formats, error behavior, versioning, design rules and module ownership before large parallel expansion.

Suggested workstreams: core/domain, data/persistence, UI/interaction, platform/integration, independent QA, performance and delivery. Activate only the relevant roles.

Verification: actual user journeys, meaningful functional/property/integration checks, data round trips, accessibility and target-platform checks, performance measurements, and a clean launch/package attempt. Document untested platforms.

Deliver source, relevant dependency lockfiles, builds when feasible, configuration examples without credentials, usage/build instructions, evidence and known limitations. A screenshot is supplemental to a functioning application.
