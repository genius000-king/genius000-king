## 0. الخلاصة التنفيذية

شغّلت الموقعين فعلياً في متصفح Chromium حقيقي (سطح مكتب 1440×900 وجوال 390×844)، وصوّرتهما، وقِست الـ DOM. النتيجة باختصار:

**الموقع ليس «فيه مشاكل» — الموقع مكسور من جذره بسبب سطر CSS واحد.**

| القياس | المتوقّع | الواقع |
|---|---|---|
| عرض المستند (سطح مكتب) | 1440px | **2352px** |
| عرض المستند (جوال) | 390px | **1712px** |
| عناصر ظاهرة من نظام الظهور | 26 / 26 | **4 / 26** — أي 22 عنصراً مخفي للأبد |
| أقسام تبدو فارغة تماماً | 0 | **6** (من أنا · الخدمات · الدفع · الطلب · الفوتر · كل عناوين الأقسام) |
| مسار الطلب | يصل للمالك | **لا يصل لأحد** — يُحفظ في ذاكرة المتصفح ويُمسح عند التحديث |
| لوحة المشرف | لوحة تحكم | **شريط فيه 12 زر** + معاينة، وعلى الجوال 7 أزرار منها خارج الشاشة |

الخبر الجيد: **المعمارية سليمة**. الكود منظّم، بلا مكتبات، بلا build، RTL صحيح، وحدات صغيرة مفصولة. المشكلة في ثلاث طبقات فقط: **أخطاء قياس قاتلة**، **طبقة بصرية باهتة**، و**لوحة مشرف بُنيت كشريط أدوات لا كلوحة تحكم**. الخطة أدناه تصلح الأولى، وتستبدل الثانية بالكامل، وتعيد بناء الثالثة من الصفر.

## 1. التشخيص — ما الذي يحدث فعلياً

### 1.1 العطل الجذري: انفجار العرض الأفقي 🔴

```css
/* css/sections/works.css */
.works__strips { display: grid; gap: var(--s-6); }   /* ← أعمدة 1fr = minmax(auto, 1fr) */
```

سلسلة السبب والنتيجة:

1. `.works__strips` شبكة بعمود `1fr`، وهذا يعني ضمنياً `minmax(auto, 1fr)`.
2. الحد الأدنى `auto` يساوي **min-content** لمحتوى العمود.
3. داخل العمود `.marquee__track` وعليها `inline-size: max-content` — أي عرض كل بطاقات المعرض مصفوفة أفقياً (~2352px).
4. `overflow: hidden` على `.marquee` يقصّ **الرسم** لكنه لا يقلّل **الحجم الجوهري** الذي يورّثه لأبيه.
5. النتيجة: العمود يتمدّد إلى 2352px، ويسحب معه `.bleed` ثم `<main>` ثم `<html>`.
6. `body { overflow-x: hidden }` لا ينقذ شيئاً لأن `<html>` هو الذي يمرّر.

**نفس العطل مكرّر** في شريط البكجات (`.bleed > .marquee`) — بكجات كاملة خارج الشاشة.

### 1.2 لماذا تبدو أقسام كاملة فارغة 🔴

هذه أخطر نتيجة للعطل السابق، ولذلك «ما في شي يشتغل»:

```css
.fx-reveal { opacity: 0; }              /* المحتوى يبدأ مخفياً */
.fx-reveal.is-in { opacity: 1; }        /* ويظهر فقط عند التقاطع */
```

`reveal.js` يستعمل `IntersectionObserver` جذره نافذة العرض. لكن بعد أن صار المستند 2352px والنافذة 1440px، البطاقات المتوسّطة تقع **خارج نافذة العرض أفقياً** ولا تتقاطع معها أبداً → لا تأخذ `.is-in` → تبقى `opacity: 0` إلى الأبد.

قياس فعلي على الجوال: **22 من 26 عنصراً عالقة مخفية**. لهذا ترى فراغات سوداء ضخمة بين الأقسام.

عيبان إضافيان في نفس الملف:
- `threshold: 0.08` — العنصر الأطول من نافذة العرض لا يبلغ 8% من مساحته أبداً.
- لا توجد شبكة أمان: لو فشل الـ JS لأي سبب، المحتوى يبقى مخفياً بدل أن يظهر.

### 1.3 مسار الطلب لا يصل لأحد 🔴

```js
// js/core/config.js
export const SUPABASE_URL = '';        // فارغ
export const SUPABASE_ANON_KEY = '';   // فارغ
export const USE_MOCK = true;          // كل شيء وهمي
```

الزبون يملأ 3 خطوات، يضغط «إرسال الطلب»، يظهر له رقم طلب جميل `APX-…`، والطلب يُكتب في **مصفوفة في ذاكرة المتصفح**. تحديث الصفحة = الطلب اختفى. المالك لا يعلم أن أحداً طلب.

### 1.4 لوحة المشرف: شريط أدوات لا لوحة تحكم 🔴

ما تراه بعد الدخول: صف واحد فيه 12 زراً، وتحته معاينة الموقع. لا شيء غير ذلك.

| المشكلة | التفصيل |
|---|---|
| لا توجد لوحة قيادة | لا إحصائيات، لا طلبات جديدة، لا نشاط أخير، لا شيء |
| لا تنقّل | كل شيء «درج ينزلق» — لا صفحات، لا مسارات، لا زر رجوع |
| مكسورة على الجوال | 7 أزرار من 12 خارج الشاشة في شريط تمرير بلا أي إشارة بصرية |
| الأدراج لا تُغلق | لا `Escape`، لا خلفية قابلة للنقر، لا حبس تركيز |
| الأدراج تتراكم | يمكن فتح «الطلبات» و«الثيم» و«التخطيط» فوق بعض، كلها `z-index: 400` |
| شريط التحرير يصطدم | `edit-bar` بـ `z-index: 300` خلف الأدراج، يطفو في زاوية الشاشة بلا معنى |
| تصادم أنماط | لوحة المشرف تستورد **نفس CSS الموقع** ثم تضيف فوقه — أي كسر في الموقع يكسر اللوحة، والعكس |
| بلا تراجع | لا Undo، لا سجل تغييرات، والحذف نهائي بمودال تأكيد واحد |

### 1.5 لوحة البكج: شبكة مسطّحة لا بينتو 🟡

```css
.pkg-block__grid { grid-template-columns: repeat(auto-fit, minmax(200px, 1fr)); }
```

كل الصور بنفس الحجم، بنفس النسبة، في صفوف رتيبة. المطلوب — كما في المرجعين البصريين — **جدار بينتو**: بلاطات بأحجام مختلفة، بلاطة بطل عريضة، بلاطات طولية بجانب مربّعة، ألوان تملأ الفراغات، إيقاع بصري.

### 1.6 الأداء 🟡

قياس على الجوال: **122 عنصراً** يحمل `data-fx` و**4 لوحات canvas** تعمل في آن واحد (نجوم + جزيئات + أثر المؤشر + سائل). على جهاز متوسط هذا استنزاف بطارية وتقطيع في التمرير — مع أن `prefs.lowPower` موجود لكنه يخفّض القيم فقط ولا يوقف مؤثراً واحداً.

## 2. القرار المعماري

### 2.1 نُبقي على المعمارية، ونستبدل الطبقات

**التوصية: لا نعيد الكتابة بـ React/Next.**

السبب: الكود الحالي وحدات ES نقية، بلا build، بلا تبعيات، ينشر على أي استضافة ثابتة، وRTL صحيح. الأخطاء ليست في المعمارية بل في CSS وفي التصميم وفي بنية اللوحة. إعادة الكتابة بإطار عمل تكلّف أسابيع وتعيد إنتاج نفس أخطاء القياس.

ما يتغيّر 180 درجة:
- **طبقة التصميم كاملة** — نظام توكنات جديد، شبكة بينتو، خلفية جديدة، طباعة جديدة، حركة جديدة.
- **لوحة المشرف كاملة** — من الصفر، معمارية مختلفة تماماً.
- **مسار الطلب** — من قاعدة بيانات وهمية إلى واتساب حقيقي.

### 2.2 التغيير المعماري الوحيد: المعاينة داخل `iframe`

اليوم لوحة المشرف **تستورد نفس ملفات الموقع وتشغّلها في صفحتها**. هذا سبب بنيوي لصنف كامل من الأخطاء: أنماط اللوحة تسرّب إلى الموقع، وأنماط الموقع تكسر اللوحة، والمؤثرات تعمل مرتين، و`document` مشترك بين الاثنين.

**الحل:** المعاينة تصير `<iframe src="/site/?preview=1">` والتواصل عبر `postMessage`.

| المكسب | التفصيل |
|---|---|
| عزل كامل | لا تصادم CSS ولا JS بين اللوحة والموقع |
| قياسات حقيقية | تصغير الـ iframe لـ 390px يعطي **نفس** ما يراه الزبون، لا محاكاة |
| نطاق عرض صحيح | `100vw` و`@media` داخل الـ iframe تقيس الـ iframe لا نافذة المشرف |
| حرية تصميم اللوحة | اللوحة تحصل على نظام تصميم خاص بها بلا قيود هوية الموقع |

### 3.2 الخلفية الجديدة — 3 طبقات، تكلفة صفر تقريباً

| الطبقة | التقنية | الغرض |
|---|---|---|
| 1 — شبكة | `background-image` بخطوط CSS + قناع شعاعي | تعطي عمقاً وانتماءً للبينتو |
| 2 — هالتان | تدرّجان شعاعيان يتحرّكان ببطء شديد (`60s`) | لون وحياة بلا إلهاء |

### 3.3 الشبكة — مكوّن `.bento` واحد يحكم الموقع

```css
@media (max-width: 640px)  { .bento { grid-template-columns: repeat(var(--bento-cols-mobile), minmax(0,1fr)); } }
```

### المرحلة 1 — إيقاف النزيف (نصف يوم) 🔴

الهدف: أن يعمل الموقع الحالي عملاً صحيحاً قبل تجميله.

| # | العمل | الملف |
|---|---|---|

| 1.5 | `reveal.js`: `threshold: 0` + `rootMargin: '0px 0px -8% 0px'` + مؤقّت أمان 1200ms يُظهر كل شيء لم يُلاحَظ | `reveal.js` |

## 5. مسار الطلب → واتساب (تفصيل تقني)

### 5.1 حقيقة يجب أن تعرفها أولاً ⚠️

**رابط `wa.me` لا يدعم إرفاق صور — نصاً فقط.** هذا قيد من واتساب نفسه، لا حل برمجي له. أي أداة تدّعي غير ذلك تكذب.

لذلك الحل ثلاثي المستوى، ويعطيك الصور في الرسالة على الجوال فعلياً:

| المستوى | الشرط | النتيجة |
|---|---|---|
| **أ — مشاركة أصلية** | جوال + `navigator.canShare({files})` | ورقة المشاركة تفتح، يختار الزبون واتساب، **الصور والنص يذهبان معاً في محادثة واحدة** ✅ |
| **ب — روابط في النص** | سطح مكتب، أو المشاركة غير مدعومة | الصور تُرفع إلى التخزين، وروابطها تُدرَج داخل نص الرسالة، ويفتح `wa.me` |
| **ج — الحافظة** | فشل الرفع أو لا اتصال | نص الرسالة يُنسخ للحافظة + يفتح `wa.me` بالنص الأساسي + تنبيه واضح |

### 5.2 مصيدة تقنية حرجة

`window.open()` بعد `await` **يحجبه المتصفح** كنافذة منبثقة. الحل الوحيد:

```js
// نفتح النافذة فوراً وبشكل متزامن داخل معالج النقر
const win = window.open('', '_blank');
try {
  const url = await buildWhatsAppUrl(state);   // الرفع والبناء بعد الفتح
  win.location.href = url;
} catch {
  win.close();
  fallbackToClipboard();
}
```

هذا السطر وحده الفرق بين «الزر يشتغل» و«الزر ما يسوي شي» — وهو من أشهر أخطاء هذا التدفّق.

### 5.3 قالب الرسالة

`js/panels/whatsapp.js` — دالة خالصة:

```js
export function buildWhatsAppMessage(order) { … }   // تعيد نصاً
export function buildWhatsAppUrl(phone, text) { … } // تعيد https://wa.me/<phone>?text=<encoded>
```

الناتج:

```

📱 التواصل: 0511572807 · واتساب
🎯 الاستخدام: تجاري — مشروع أو متجر

• غلاف بودكاست ×1 (طلب خاص)
```

قواعد البناء:
- الرقم يُقرأ من `site_content.whatsapp` — **قابل للتغيير من لوحة المشرف**، لا مكتوب في الكود.
- تنظيف الرقم: `String(v).replace(/\D/g,'')` مع إضافة رمز الدولة إن غاب.
- الطول: `wa.me` يبدأ يتعطّل بعد ~2000 حرف. الوصف مقيّد بـ 500، وإن تجاوز الإجمالي الحدّ نستبدل قائمة المرفقات برابط واحد لصفحة الطلب.
- ترميز `encodeURIComponent` كامل — يشمل الأسطر الجديدة والإيموجي والعربية.

### 5.4 ما يحدث خلف الكواليس

```
[إرسال الطلب]
   ├─ 1. فتح نافذة فارغة (متزامن) ─────────────────┐
   ├─ 2. توليد رقم الطلب                           │
   ├─ 3. رفع المرفقات إلى Supabase Storage         │
   ├─ 4. حفظ الطلب في جدول orders (channel: 'whatsapp')
   │      ↳ يفشل بصمت — لا يوقف المستخدم أبداً
   ├─ 5. بناء نص الرسالة                           │
   ├─ 6. مسار أ: navigator.share({files, text})    │
   │      مسار ب: win.location = wa.me URL ────────┘
   └─ 7. شاشة نجاح: رقم الطلب + «فتح واتساب مرة أخرى» + «نسخ الرسالة»
```

**نقطة مهمة:** الطلب يُحفظ في القاعدة **قبل** فتح واتساب. لو الزبون فتح واتساب ولم يضغط إرسال، أنت ما زلت ترى الطلب في لوحتك. هذا يحمي من ضياع العملاء.
